# 深海下潜末帧接龙

制作"一次下潜、一镜到底感"的深海探索短片。核心只有三条：**情绪弧先行**（先定观众从愉快到紧张的曲线，再分段）、**视频段每段只喂上一段的最后一帧**、**深度数字一律后期渲染**（视频模型画的数字必错，UI 必须逐帧程序渲染叠加）。

目标产物：16:9、1280×720、24fps、**精确 60.000s／1440 帧**，AAC 环境音轨（纯环境声，无旁白无配音，除非用户另行指定）。完整实录见 [references/deep-sea-8000-case.md](references/deep-sea-8000-case.md)（0–8000m 机舱第一视角，用户定版）；六段提示词原文见 [references/segment-prompts.md](references/segment-prompts.md)。

## 开工前先定四件事

向用户确认或从其指令中提取：

1. **视角**：艇外同向跟拍（镜头在潜艇外、与艇同向，机位在段间按脚本轮换：后方／侧面／后侧方／后上方／低角度近景）或机舱第一视角（镜头固定在舱内看舷窗，全程不动机位）。两种视角的运镜模板不同，开工前必须定死。
2. **目标深度与六段深度表**：总深度（如 5000m、8000m）拆成 6 段的起止深度。深度带划分尽量贴海洋学分带（阳光带 0–200m、暮光带 200–1000m、午夜带 1000–4000m、深渊带 4000–6000m、超深渊带 6000m 以下），每段的起止深度就是后面 UI 深度曲线的关键点，必须先定。
3. **情绪弧与每段唯一事件**：六段是一个情绪曲线（如：明亮愉快 → 安静神秘 → 阴暗不安 → 危险紧张 → 恐怖 → 敬畏收尾）。**每段只发生一件事**（一只生物、一个地貌、一次遭遇），段内不换景——段内多事件是构图漂移和"切镜感"的主要来源之一。
4. **硬约束**：画面文字（无中文／无任何文字）、人物（出现／不出现）、声音（纯环境声／静音／配音）逐项向用户确认并写进每段提示词，不要默认。

## 环境

- 图生视频单次生成上限 10s，先跟用户说清 60s 必须 6 段拼。生成视频时输出目录传**绝对路径**，不要用 `~` 或相对路径。
- 后期只需要 FFmpeg 与 Python 3＋Pillow（渲染 UI 帧序列）。全部在本机完成，不需要用户安装任何东西。

## 每段提示词的固定写法

- **首帧锁定句**：第 1 段纯文本生成；第 2 段起第一句写「以参考图为首帧，构图与光线完全一致地开始／Use the reference image as the first frame, start with exactly the same composition and light」，参考图只用上一段的最后一帧（`scripts/extract_last_frame.sh`，即 `ffmpeg -sseof -0.05` 提取）。
- **运镜模板句**（艇外版）：镜头在艇外伴飞，与潜艇保持恒定的相对位置，全段只做极慢的推近——不环绕、不迎头、不摇摆、不切镜，潜艇始终向前航行。六段的机位轮换（后方／侧面／后侧方／后上方／低角度近景）在开工时排成表，不要临场改。完整新版模板见 [references/segment-prompts.md](references/segment-prompts.md) 的艇外版一节。
- **结构锁定句**：艇外版锁主体——「同一艘白色深潜器，形状与大小不变，不新增其他载具」；机舱版锁舱内构图（见下节，这是本玩法最容易翻车的地方）。
- **声音段**：每段单写一段声音设计——环境声元素随深度变化（浅层气泡与水流 → 深层声呐、艇体受压吱嘎、巨物低鸣），并明确「无音乐、无人声、无旁白」（或按用户定的约束）。
- **负面句**：无字幕、无水印、无台标；如用户要求无文字，再加「画面中不出现任何文字、字母、数字，仪表只画抽象图形」——舱内仪表一旦让模型画数字，必是乱码。

## 机舱视角的构图漂移（核心坑，案例实测）

机舱第一视角最大的坑不是接点，而是**段内后半段镜头被模型"推出舱外"**：遇到大生物时模型想推近拍满框，舷窗和舱体就消失了，观众感觉"几秒就切一次镜"。8000m 案例 v1 的实测漂移：6 段里 4 段在后半段丢了舷窗（8s 全幅珊瑚、28s 巨物满框、38s 乌贼满框、48s 巨兽满框），且每段舷窗形状/大小、仪表盘位置都在变。对策按有效程度排：

1. **构图锁逐字重复**：每段提示词都原样带同一段构图锁——机位完全固定、舷窗居中且尺寸位置不变、舱壁与两侧仪表每帧都在、镜头永不离舱、永不切全幅窗外。只在第 1 段写、后面段不写，等于没写。
2. **生物保持距离**：遭遇生物一律写「在舷窗外 2–3 米外」，不贴玻璃、不占满框。贴玻璃和满框是触发出舱推近的最强诱因。
3. **每段一件事**（见开工四件事之三）。
4. **验收门**：每段生成后抽 0／2.5／5／7.5／9.9s 五帧，**舷窗必须五帧全在**，任一帧丢窗该段先重滚再进拼接（`scripts/verify_frames.sh` 的 gate 模式负责抽这五帧）。
5. **可选增强——双图母图法**：每段除上一段末帧外，再喂同一张"锁舱母图"（全片舱内构图最稳的一帧，如案例的第 1 段 5s 帧）专锁舱内。此法**有意偏离纯末帧接龙**，使用时必须在交付说明里注明。

**一条诚实的结论**（案例用户定版结果）：v1 只用了对策 1–3＋硬拼，用户判定为最佳版；后来做的 v2 在此基础上加了接点交叉溶解＋整体回拉时标"修平顺"，反而落选。**修补术不能替代段内稳定，且观众未必买溶解的账**——先把段内构图稳住，拼接保持硬拼默认，溶解只作可选。

## 深度 UI（后期渲染，绝不让模型画）

- 面板内容：DEPTH 大读数＋单位 **m**、0–目标深度标尺条（随深度填充）、下降速度、TARGET、分带名、STATUS（CALM 绿 → CAUTION 黄 → DANGER 红，随深度推进变色）。用户要求无中文时，UI 全部用英文——UI 是全片唯一允许的文字。
- **深度必须按六段关键点分段计速，不是全程匀速**：t=0/10/20/30/40/50/60s 对应各段起止深度，段内线性插值。匀速滚到总深度会和画面内容对不上（例：8000m 案例 10s 时画面还在阳光带末端，匀速读数会是 1333m，错得离谱；分段计速是 200m，与画面一致）。
- 做法：`scripts/make_depth_hud.py` 按关键点表逐帧渲染带透明通道的面板帧序列（1440 帧），`scripts/overlay_hud.sh` 用 ffmpeg overlay 叠到成片右侧。改目标深度/分段只改脚本顶部的 KEYPOINTS 与 ZONES 两张表。
- 叠完必须抽帧核对读数：至少查每段中点（如 5/15/25/35/45/55s）的读数与该段深度区间中点一致。

## 拼接（精确时长是硬指标）

六段同为 1280×720／24fps 时，用 `scripts/concat_exact_60s.sh`：ffmpeg concat **流复制**拼接并用 `-frames:v 1440` 锁死总帧数，音轨保留各段环境声直接衔接。注意：各段音轨直接 concat 时长可能多出零点几帧，成片 ffprobe 应为 60.000s（视频轨为准）；若重编码拼接，必须加 `-frames:v 1440` 并把音轨 `atrim=0:60`，直接拼不管帧数会多帧超长，不合格。

可选：接点交叉溶解（xfade 0.4s×5 处＋acrossfade 音频，总时长缩短 2s，再 setpts/atempo 回拉到 60s）。案例实测用户不偏好此版，仅在用户明确要求"过渡更柔"时使用，并在交付时说明。

## 验证与交付（不许跳过）

用 `scripts/verify_frames.sh` 一次做完：

- ffprobe 实测并报出：1280×720、24fps、1440 帧、60.000s、AAC 音轨。
- 音轨用 volumedetect 实测有声（案例 v1：mean −18.9dB）。**实测有声 ≠ 试听过**，没实际听就不要说听过。
- 五个接点抽帧对比（9.9 vs 10.1、19.9 vs 20.1、…、49.9 vs 50.1）：构图应连续、无跳帧。
- 每段五帧构图门（机舱版）：舷窗五帧全在；艇外版查主体形状/数量未增生。
- UI 读数抽帧核对（见上节）。

交付：成片＋代表静止画，并如实列**偏差清单**（哪段漂了、漂成什么样）。技术验证、制作者视觉自检、用户验收三者分开报，不要把自检通过说成用户定版。
