# 地标建筑 3D 末帧接龙

制作“真实几何打底 × AI 写实化”的地标建筑短片。核心只有两条：**起点静止画必须来自真实三维几何**（开放数据或按规制建模），**视频段每段只喂上一段的最后一帧**。先识别用户要做哪座建筑、走哪条数据路线；已确认的案例参数和验收结论不要在新案例里重置。

目标产物：16:9、1280×720、24fps、**精确 30.000s／720 帧**，带 AAC 环境音轨。灵感来源为 @noel_ai_lab 的大阪城帖（PLATEAU＋Blender 静止画＋3×10s 末帧接龙）。两个完整实录见 [references/osaka-castle-case.md](references/osaka-castle-case.md)（数据路线）与 [references/taihedian-case.md](references/taihedian-case.md)（建模路线），做新案例前先读与所选路线对应的那份。

## 开工前先定四件事

向用户确认或从其指令中提取：①建筑与城市；②**标志性识别三件套**（静止画验收标准，如太和殿＝三层白台基＋红墙十一间＋黄色重檐庑殿顶）；③第2段要穿的门；④第3段全景要收进的周边地标。缺识别三件套时先和用户一起定下来，不要开工后再补。

## 环境

- Blender 官方 Linux 便携版（4.2 LTS 即可）解压免安装，用 `blender --version` 和无头 `import bpy` 验证。Blender 只出静止画，不渲染视频，也不需要装在用户电脑上。
- 无 GPU、内存约 8G 的环境用 **Cycles CPU**（64 samples＋去噪，1280×720 约 2 分钟/帧）。EEVEE 若报缺 libEGL 直接改 Cycles，不要耗时间补库。
- 图生视频单次生成上限 10s，先跟用户说清 30s 必须 3 段拼。生成视频时输出目录传**绝对路径**，不要用 `~` 或相对路径。

## 数据源决策（按顺序试，先核查再导入）

1. **日本建筑 → PLATEAU**：官方配信 API 按坐标查 `https://api.plateauview.mlit.go.jp/datacatalog/citygml/r:{经度},{纬度}`，只下目标网格的 bldg（城墙/石垣加 cons；dem 单文件 300–500MB，非必要不下）。**先在 GML 文本里核查**主体是否实名存在、LOD 几、面数、实测高度，与真实尺寸对不对得上。建筑本体往往无纹理，渲染时按几何面方向近似上色（斜面＝瓦色、竖面＝墙色、低部＝石色），属正常状态、如实说明。
2. **平台模型（Sketchfab CC、CGTrader 免费等）**：下载都要平台账号。接口返回 401 或页面要求登录时，停下来把链接给用户、请其用自己账号下载后放进项目目录，**不要绕过登录**。
3. **匿名可得的模型必须先验**：导入 Blender 实测渲染一张验可辨认度。教训：某 GitHub 故宫 GLB 只有 244 面，渲染是红盒子加平板盖，不可辨认，必须弃用。OSM 轮廓挤出只有平顶盒子、没有标志性屋顶，同样不可作主体。
4. **都拿不到 → 程序化建模**：查**两个公开来源**核对关键尺寸（面阔/进深/总高/台基高/屋顶形式），在 Blender 里用 Python 按米制比例建模、扁平上色。规制尺寸必须真；细部（斗拱、栏杆雕刻、屋面举折曲线）做建模级近似，交付时逐项列出。太和殿即按此建成：面阔 63.96m、进深 37m、殿高 26.92m、三层台基 8.13m、通高 35.05m、重檐庑殿顶、大吻 3.4m。

## 静止画验收闸门（不通过不许往下走）

- 规格：1280×720；机位取主体最佳观赏面（通常东南侧）高位斜俯瞰，40mm 左右，主体居中、占画面高度约一半，前景留出广场/入口方向。
- 标准：**第一眼能认出这座建筑**——识别三件套缺一不可、比例不离谱。制作者必须亲自看图判定，不以“渲染成功”代替“可辨认”。
- 不达标就调材质/机位重渲（先出小样迭代，3 轮内定位问题）；认不出来绝不进入视频段。把静止画先发给用户看。
- 静止画是干净的 3D 模型感（扁平色块、无真实纹理）是正常的：写实质感由视频模型补全，与原帖同性质，不要拿 AI 生成图冒充 Blender 渲染。

## 三段视频（图生视频，每段 10s）

每段提示词的固定写法：

- 第一句锁定首帧：「以参考图为首帧，构图与光线完全一致地开始」，并写明画面从 3D 模型质感自然过渡为真实实拍质感，点名真实材质（瓦、石材、墙面、天空、远景）。
- 运镜写**显式时间关键帧**（0s／2.5s／5s／7.5s／10s 各在哪个方位/高度）。只写一句“环绕一周”，镜头大概率只转约半圈。
- 每段带结构锁定句：「建筑结构不变形，台基始终 X 层、屋顶始终 X 层，不新增或减少建筑」，再加「无人物特写、无字幕、无水印、无旁白，只有自然环境音」。

运镜设计：

- **第1段 环绕**：从静止画机位绕主体一周，末帧**落在正面低位**（正对入口/台阶）。落点是下一段的入口，比环绕本身更重要。
- **第2段 穿门上升**：三拍——下降推近朝正门飞 → 低空穿过门洞（穿过阴影再见光）→ 沿台阶/墙面贴体上升、掠过各层屋檐 → 停在屋顶最高点近景特写（塔尖/正脊/大吻）。
- **第3段 空中俯瞰**：从特写后退爬升 → 主体全貌与基座显露 → 升到高空大全景，把约定的周边地标（建筑群、水面、城市天际线）收进画面停稳。后拉通常会提前到位、后半程缓漂，属已知现象，交付时说明即可。

**接龙铁律**：第2段只喂第1段的最后一帧，第3段只喂第2段的最后一帧（用 `scripts/extract_last_frame.sh`，即 `ffmpeg -sseof -0.05` 提取），不许再喂静止画或任何其他参考——这是这个玩法的核心，也是它唯一的漂移来源。

## 拼接（精确时长是硬指标）

三段同为 1280×720／24fps 时，用 `scripts/concat_exact_30s.sh`：ffmpeg concat 重编码，**必须加 `-frames:v 720` 并把音轨 `atrim=0:30`**。直接拼会多出 1 帧变成 30.07s，不合格。

## 验证与交付（不许跳过）

用 `scripts/verify_frames.sh` 一次做完技术校验与接点抽帧：

- ffprobe 实测并报出：1280×720、24fps、720 帧、30.000s、AAC 音轨。
- 每段抽帧 0／2.5／5／7.5／9.9s 逐张看：运镜关键帧是否到位、写实化是否完成。
- 两个接点抽帧对比（成片 9.9s vs 10.1s、19.9s vs 20.1s）：构图应几乎一致、无跳帧感。
- **专查结构增生**：屋顶层数、台基层数有没有变多，画面里有没有多出不存在的建筑/物件（原帖作者的东京站前作翻过“时钟越变越多”的车）。发现增生在交付里点名。

交付物：成片＋Blender 静止画。交付说明里**如实列偏差清单**（如起点段前约 2s 仍是模型感、第3段后半程缓漂、视频模型自创的地理与细节发挥、程序化建模的近似清单），不要把三段拼接说成一镜到底；分别说明技术验证、制作者视觉自检和用户验收状态。

## 常见坑速查

- 视频单次上限 10s：30s 必须 3 段拼，别指望一次生成。
- 拼接不截帧数 → 30.07s；必须 `-frames:v 720`。
- 环绕只写一句话 → 只转约 180°；必须写显式方位关键帧并抽帧验。
- 末帧接龙多喂一张参考图 → 不是这个玩法了，接点反而容易跳。
- 平台模型下载 401/要登录 → 停下让用户下，不要找绕过。
- 匿名模型不验就用 → 可能只有几百个面、根本不可辨认。
- 生成视频的输出目录用相对路径或 `~` → 文件落到找不到的地方；传家目录绝对路径。
